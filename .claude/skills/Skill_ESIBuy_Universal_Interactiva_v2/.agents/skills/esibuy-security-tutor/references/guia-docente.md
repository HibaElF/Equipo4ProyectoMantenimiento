# Guía docente: calidad, diversidad y didáctica

## Selección de escenarios
Priorizar diversidad de activos, fronteras de confianza, actores y consecuencias, y evitar duplicar la misma hipótesis con títulos distintos. Comenzar por funcionalidades realmente existentes. Distribuir dificultad introductoria/intermedia/avanzada si el grupo lo pide.

## Evaluación explicativa por caso
Cada caso debe incluir: qué funcionalidad protege o amenaza, evidencia exacta o declaración de hipótesis, motivo de selección, razonamiento técnico, control potencial, prueba observable y errores conceptuales frecuentes. No exagerar impacto, explotabilidad o evidencia.

## Consistencia
1. Un árbol representa un objetivo adversario con lógica OR/AND válida.
2. Un mal uso describe un flujo adversarial contra un caso legítimo.
3. Un caso de uso de seguridad exige una respuesta defensiva del sistema verificable.
4. Muchos-a-muchos: no forzar AT=MU=SUC ni una relación 1:1.
5. Un escenario hipotético sirve para aprender, pero no demuestra una vulnerabilidad.
6. Mantener estado de prueba: propuesta, añadida no ejecutada, ejecutada con resultado.

## Cierre del alumno
Pedir reflexión breve opcional: controles prioritarios, riesgo residual y aprendizajes. La rúbrica existente puede usarse para autoevaluación, pero no asignar calificación numérica sin solicitud.
